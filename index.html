How these personas were built
Each persona is grounded in real PNR data fields (SSR codes, RBD fare class, meal codes, seat map history) and loyalty database fields (tier, transaction log, ancillary purchase history). In production, JourneyMate retrieves this profile via read-only API from the airline's Navitaire or Altéa PNR system at the moment of disruption. The K-means segmentation model runs monthly on 12-month rolling booking + ancillary data, mapping each traveller to their closest cluster in real time at disruption trigger. Source: IATA passenger segmentation methodology.
Backend Data & Methodology
Every number in the JourneyMate prototype is sourced and traceable. This page documents the RAG architecture, cost assumptions, ancillary revenue methodology, and NPS model behind every metric shown.
Production RAG Architecture
In the prototype, context is pre-defined for demonstration. In production, JourneyMate retrieves live data from three sources at the moment of disruption.
RAG Pipeline — step by step
1
Disruption trigger
Flight Information System (OAG / FlightAware API) detects delay ≥90 min, cancellation, or diversion. Event fires with flight number, reason code, new ETA, affected PNR list.
↓
2
Profile retrieval — Source 1
PNR system API call (Navitaire / Altéa / Amadeus) → retrieves traveller profile: tier, seat preference, meal choice, past ancillary history, contact channel. Read-only, sub-200ms.
↓
3
Inventory retrieval — Source 2
Real-time partner API calls: lounge availability (Priority Pass API), hotel inventory (Amadeus Hotel API), transfer availability, next flight availability (GDS feed). Simultaneous.
↓
4
Policy retrieval — Source 3 (RAG)
Vector similarity search in Pinecone DB against embedded DGCA policy corpus, airline fair practice guidelines, tier entitlement rules. Returns top-k relevant policy chunks. Auto-updated when DGCA publishes new circulars.
↓
5
Context assembly + generation
Profile + inventory + policy assembled into prompt context. Passed to Claude Haiku (simple delays) or Sonnet (complex cancellations/diversions) based on severity classifier.
↓
6
Delivery + feedback loop
Personalised message delivered via WhatsApp / push / SMS. Traveller accept/dismiss logged → feeds segmentation model. System gets smarter with every disruption handled.

Why RAG and not fine-tuning? DGCA policy changes frequently. Fine-tuning bakes knowledge at training time — it goes stale. RAG retrieves at inference time — always current. For policy-critical content like compensation entitlements, retrieval-grounded generation is non-negotiable. The LLM's job is language. The data pipeline's job is facts.

Formula: Each 1-point NPS improvement = ~0.4% reduction in churn probability (Bain 2022).
46-point improvement (−28 to +18) = ~18% churn reduction.
At scale: 1.5M disrupted Platinum pax × 18% churn reduction × ₹10L LTV × 5% annual yield = ₹135 crore LTV protection annually
Service recovery paradox: Research shows passengers who experience disruption AND are handled exceptionally well score higher NPS than passengers who were never disrupted. JourneyMate is designed to trigger this effect systematically at scale.
